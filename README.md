# 游间 · 小游戏大厅

一个仓库，一次启动。大厅与两款小游戏的完整源码都在这里，直接进入游戏，不依赖原来的项目目录或外部服务。

- **逸剑风云决 · 问剑长歌**：三章武侠故事、九张地图、回合交锋、悬赏与剑冢。
- **余烬 · 荒野生存手记**：探索六片区域，采集、制作、经营营地，熬过七个夜晚。
- 大厅提供分类、搜索、收藏、最近游玩、随机游玩、实景预览和操作说明。
- 游戏页提供返回大厅、操作指南和全屏按钮；支持电脑与手机布局。

## 开始游玩

Windows 下双击 **`start.cmd`**，会启动本地预览并打开浏览器。需要 Node.js 18 或更新版本，无需安装依赖。

也可以在本目录运行：

```sh
npm start
```

打开 **http://127.0.0.1:4177**，在大厅点击「开始游玩」。终端按 `Ctrl+C` 停止预览。

也支持直接打开根目录的 `index.html`。推荐持续使用上面的固定地址，以便浏览器保持一致的存档位置。如果 4177 已被占用，可以先关闭旧预览，或者在 PowerShell 中执行 `$env:PORT = '4180'` 后重新启动；更换端口会改变存档所属地址。

## 存档与原项目迁移

此次整合保留了两款游戏原有的全部源码、操作与存档键。大厅只保存自己的收藏和游玩记录，不读取、修改或清空游戏进度。

浏览器存档属于原来的打开地址，**复制源码不会自动搬运旧地址下的存档**。如果原项目已经有进度：

1. 在原地址打开原游戏并导出存档。
2. 从新大厅进入同一款游戏，然后导入。
3. 逸剑风云决在「游玩指南」中操作；余烬在右上角「存档与设置」中操作。

隐私窗口、清除站点数据或更换浏览器都会影响本地记录。游戏导出的存档文件可以自行备份。大厅从未自动开始新周目或重置任何存档。

## 一个仓库管理全部游戏

```text
ai-game/
├─ index.html                游戏大厅
├─ play.html                 统一游玩页面
├─ hall/
│  ├─ catalog.js             游戏目录：名称、路径、封面、介绍、操作
│  ├─ library.js             收藏、最近游玩与筛选
│  ├─ app.js                 大厅交互
│  ├─ player.js              游戏加载与全屏
│  ├─ ui.js                  详情、指南与界面图标
│  └─ styles.css             大厅与游玩外壳样式
├─ games/
│  ├─ fengyunjue/            逸剑风云决完整源码与原有测试
│  └─ jihuan/                余烬完整源码与原有测试
├─ assets/previews/          从游戏本身生成的场景图与截图
├─ scripts/                 统一预览、构建与验证
├─ tests/                   大厅与发布边界验证
├─ start.cmd                Windows 一键启动
└─ package.json             全部常用命令
```

只需在根目录管理 Git。游戏目录不包含嵌套 Git 仓库，也不需要子模块。两款游戏的原目录保持原样；后续修改以此仓库内的源码为准。

游戏页面使用独立的 iframe，保留各自的脚本、样式和快捷键，避免互相覆盖。大厅不需要同时运行两个游戏。游戏地址必须来自目录登记，不能通过参数加载任意网页。

## 统一发布

```sh
npm run build
npm run preview
```

构建将完整可玩的静态站点输出到 `dist/`。可以把这个目录部署到支持静态文件的网站服务，包括域名根目录或子目录，不需要后端或数据库。`npm run preview` 使用同一个默认端口预览构建产物，需要先停止已有预览。

发布内容包含大厅、游戏源码及静态素材，不包含测试、开发脚本、原项目截图缓存或 Git 文件。构建只替换本项目生成的 `dist/`；遇到不属于本项目的已有目录会停止并保留其内容。

## 添加下一款小游戏

1. 将可独立运行的网页游戏放入 `games/<id>/`，保留 `index.html` 和相对资源路径。
2. 在 `hall/catalog.js` 的 `games` 数组增加登记，参考现有游戏填写唯一的 `id`、入口、类别、封面、完整截图、介绍和操作。`readySelector` 使用游戏加载后必定存在的元素选择器。
3. 把封面和完整截图放进 `assets/previews/`。大厅自动生成卡片、分类、收藏入口和游玩页面；构建自动收集新游戏的运行资源。
4. 重新启动本地预览，然后执行 `npm test` 和 `npm run build`。

如果新游戏需要后端或编译步骤，应先为它接入对应的构建方式。本仓库现有两款游戏没有此类依赖。

## 验证

```sh
npm test
npm run test:browser
```

`npm test` 不需要安装依赖，运行大厅存储与筛选、静态资源与预览访问边界、余烬全部规则验证，以及逸剑风云决规则验证和 19 场主线策略试跑。

浏览器验证需要 Playwright，可以安装：

```sh
npm install --no-save playwright
npx playwright install chromium
npm run test:browser
```

也可以设置 `PLAYWRIGHT_MODULE` 指向已有 Playwright 包，使用 `BROWSER_PATH` 指定浏览器。在 Windows 上会优先使用已安装的 Edge。测试使用全新的浏览器环境，不接触个人浏览器存档；结果截图保存在被 Git 忽略的 `test-results/`。

`npm run test:browser:dist` 验证构建产物；`node scripts/capture-previews.cjs` 可重新生成现有两款游戏的实景封面与完整截图。各游戏原来的详细说明和可选测试仍保留在自己的目录中。
