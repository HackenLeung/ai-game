# 游间 · 小游戏大厅

一个仓库，一次启动。大厅与三款小游戏的完整源码都在这里，直接进入游戏，不依赖原来的项目目录或外部服务。

- **逸剑风云决 · 问剑长歌**：三章武侠故事、九张地图、回合交锋、悬赏与剑冢。
- **余烬 · 荒野生存手记**：探索六片区域，采集、制作、经营营地，熬过七个夜晚。
- **深渊回响 · 牌组构筑**：三名角色、101 张卡牌、十二章共 180 层爬塔，遗物、药水与事件构筑。
- 大厅提供分类、搜索、收藏、最近游玩、随机游玩、实景预览和操作说明。
- 游戏页提供返回大厅、操作指南和全屏按钮；支持电脑与手机布局。

开发与维护请先阅读 [项目开发规范](DEVELOPMENT.md)，其中约定了游戏接入、界面适配、存档兼容和验证方式。

## 开始游玩

Windows 下双击 **`start.cmd`**，会启动本地预览并打开浏览器。需要 Node.js 18 或更新版本，无需安装依赖。

也可以在本目录运行：

```sh
npm start
```

打开 **http://127.0.0.1:4177**，在大厅点击「开始游玩」。终端按 `Ctrl+C` 停止预览。

也支持直接打开根目录的 `index.html`。推荐持续使用上面的固定地址，以便浏览器保持一致的存档位置。如果 4177 已被占用，可以先关闭旧预览，或者在 PowerShell 中执行 `$env:PORT = '4180'` 后重新启动；更换端口会改变存档所属地址。

## 让 AI 来玩游戏

有两种玩法：在网页里看 AI 边玩边讲，或在命令行里跑一局并留下记录。两者共用同一套模型注册表（[scripts/ai-core.cjs](scripts/ai-core.cjs)）、提示词与动作计划（[hall/ai-observer.js](hall/ai-observer.js)）。

### 网页版：AI 游玩按钮

启动预览（`npm start`）后进入任一游戏页面，点右上角的「AI 游玩」，面板里可以：

- 在下拉框里切换模型；
- 设置步数与每步间隔；
- 点「开始游玩」看 AI 在真实画面里自己做决定，随时可以「停止」接管；
- 点「配置模型…」接入自己的模型与接口。

面板只在用本仓库的预览服务（`npm start` 或 `npm run preview`）时可用：模型地址与密钥都留在 Node 端，浏览器只拿到模型名称和决定；直接打开 HTML 或部署到静态站点时，面板会提示需要先启动本地预览。

### 配置模型与接口

「配置模型…」表单可以填名称、接口地址、模型名称、密钥和决策方式，保存后立刻出现在模型下拉里。**测试连接只做一件事**：请求一次 `<接口地址>/models`，把返回的模型数量与名称列表填进模型名称输入框（带下拉建议），确认这个地址有模型可用即可。

配置保存在仓库根目录的 `.ai-config.json`（已被 Git 忽略，不会提交、也不会进入发布产物），首次运行自动生成三个预设：

| id | 名称 | 接口地址 | 模型 |
| --- | --- | --- | --- |
| `chat` | 对话模型 · deepseek-v4.1-flash | `http://127.0.0.1:3425/v1` | `localhost/cn:deepseek-v4.1-flash` |
| `jev` | 决策模型 · jev-latest | `http://127.0.0.1:8899/v1` | `jev-latest` |
| `gateway` | 本地网关 · 8080 | `http://localhost:8080/v1` | `cn:deepseek-v4.1-flash` |

`gateway` 的密钥在首次生成配置时从 `~/.codex/config.toml` 里取一次；读不到就留空，在表单里补填即可。密钥只会写进这个本地文件并在服务端使用，接口返回给浏览器的数据里不含密钥；表单里留空表示沿用已保存的密钥，但改了接口地址就得重新填一次，免得密钥被带到别的地址上。想改路径可以用环境变量 `AI_CONFIG_PATH`。配置文件读不出来时会先备份成 `.ai-config.json.recovery`，不会直接覆盖。

### 命令行版

`scripts/ai-player.cjs` 把当前画面整理成文字交给模型，由模型自己决定下一步，再通过真实鼠标点击操作游戏。终端会逐步打印它的判断，同时留下截图、延时回放和完整的决策记录。`--engine` 就是上面的配置 id，所以自定义的模型也能直接在命令行使用。

```sh
npm run ai:play                      # 用 chat 预设玩余烬，最多 40 步
npm run ai:play -- --headed          # 打开浏览器窗口，现场看它玩
npm run ai:play -- --turns=200       # 跑一局长局，结束时自动合成延时回放
npm run ai:play -- --engine=jev      # 改用 jev 决策模型
npm run ai:play -- --engine=gateway  # 用配置文件里的任意一条
```

### 两种决策方式

| 决策方式 | 做法 | 说明 |
| --- | --- | --- |
| `chat`（默认） | 让对话模型输出 `{"thought","action","id"}` | 任何 OpenAI 兼容的 `chat/completions` 接口都能用 |
| `jev` | 枚举本回合所有可行动作，让模型用 typed question 选一个 | 需要 `choice` / `noul` 支持，例如 jev-latest |

`jev` 方式下，脚本把画面里的动作整理成候选键（`gather:<id>`、`feedFire:`、`sleep:`、`travel:<id>`、`craft:<id>`、`choose:<id>`，外加兜底的 `wait:`），连同每项的收益与消耗一起提交给 `move`（choice）与 `risk`（noul）两个问题；风险分达到阈值（默认 0.6）就带提示重问一次 `move`。jev 没有思考文字，记录里改用选择、概率分布、置信度与风险分。

命令行也可以用 `--base-url=` 与 `--model=` 临时覆盖某条配置，密钥仍只从配置文件与环境变量读取，不写入仓库。

其他参数：`--turns=60` 步数上限、`--delay=600` 每步间隔毫秒、`--game=<id>` 选择目录里登记的游戏、`--screenshots=false` 关闭逐步截图、`--video` 额外录制完整实时录像（文件很大，通常不需要）、`--dry` 只打印画面、不调用模型。

结果写入被 Git 忽略的 `test-results/ai-play/`：`transcript.md` 是逐步画面与决策记录，`turn-*.png` 是每一步的截图，结束时用这些截图自动合成一段加速的 `timelapse.mp4` 回放，`summary.json` 汇总步数、结果与每一手动作。逐步截图是完整分辨率的 PNG，长跑会占用较多磁盘，不需要时加 `--screenshots=false`。

接口可能有每分钟请求数限制，超过会返回 429；命令行与网页面板同时跑同一个接口会互相抢额度，长跑时把间隔放大或错开运行。

目前只有余烬接入了 AI 游玩（回合制行动，适合模型逐步决策）。深渊回响（卡牌回合制：出牌、选路线、拿遗物）和逸剑风云决（需要在场景中移动、与人物交互再进入回合交锋）都还没适配：在这两款游戏里打开面板会直接说明情况，「开始游玩」保持禁用状态，不会空跑。

新增适配时要写的两处：在 [hall/ai-observer.js](hall/ai-observer.js) 里补 `readObservation()` 的选择器与 `planAction()` 的点击步骤，并把游戏 id 加进同一文件的 `SUPPORTED_GAMES`；命令行与网页面板会一起生效。

## 存档与原项目迁移

此次整合保留了三款游戏原有的全部源码、操作与存档键。大厅只保存自己的收藏和游玩记录，不读取、修改或清空游戏进度。

浏览器存档属于原来的打开地址，**复制源码不会自动搬运旧地址下的存档**。如果原项目已经有进度：

1. 在原地址打开原游戏并导出存档。
2. 从新大厅进入同一款游戏，然后导入。
3. 逸剑风云决在「游玩指南」中操作；余烬在右上角「存档与设置」中操作；深渊回响在右上角「存档与设置」中操作。

隐私窗口、清除站点数据或更换浏览器都会影响本地记录。游戏导出的存档文件可以自行备份。大厅从未自动开始新周目或重置任何存档。

## 一个仓库管理全部游戏

```text
ai-game/
├─ index.html                游戏大厅
├─ play.html                 统一游玩页面
├─ hall/
│  ├─ catalog.js             游戏目录：名称、路径、封面、介绍、操作
│  ├─ library.js             收藏、最近游玩与筛选
│  ├─ app.js                 大厅交互
│  ├─ player.js              游戏加载与全屏
│  ├─ ui.js                  详情、指南与界面图标
│  └─ styles.css             大厅与游玩外壳样式
├─ games/
│  ├─ fengyunjue/            逸剑风云决完整源码与原有测试
│  ├─ jihuan/                余烬完整源码与原有测试
│  └─ abyss/                 深渊回响完整源码与规则测试
├─ assets/previews/          从游戏本身生成的场景图与截图
├─ scripts/                 统一预览、构建与验证
├─ tests/                   大厅与发布边界验证
├─ DEVELOPMENT.md           项目开发规范
├─ start.cmd                Windows 一键启动
└─ package.json             全部常用命令
```

只需在根目录管理 Git。游戏目录不包含嵌套 Git 仓库，也不需要子模块。三款游戏的原目录保持原样；后续修改以此仓库内的源码为准。

游戏页面使用独立的 iframe，保留各自的脚本、样式和快捷键，避免互相覆盖。大厅不需要同时运行三款游戏。游戏地址必须来自目录登记，不能通过参数加载任意网页。

## 统一发布

```sh
npm run build
npm run preview
```

构建将完整可玩的静态站点输出到 `dist/`。可以把这个目录部署到支持静态文件的网站服务，包括域名根目录或子目录，不需要后端或数据库。`npm run preview` 使用同一个默认端口预览构建产物，需要先停止已有预览。

发布内容包含大厅、游戏源码及静态素材，不包含测试、开发脚本、原项目截图缓存或 Git 文件。构建只替换本项目生成的 `dist/`；遇到不属于本项目的已有目录会停止并保留其内容。

## 添加下一款小游戏

1. 将可独立运行的网页游戏放入 `games/<id>/`，保留 `index.html` 和相对资源路径。
2. 在 `hall/catalog.js` 的 `games` 数组增加登记，参考现有游戏填写唯一的 `id`、入口、类别、封面、完整截图、介绍和操作。`readySelector` 使用游戏加载后必定存在的元素选择器。
3. 把封面和完整截图放进 `assets/previews/`。大厅自动生成卡片、分类、收藏入口和游玩页面；构建自动收集新游戏的运行资源。
4. 重新启动本地预览，然后执行 `npm test` 和 `npm run build`。

如果新游戏需要后端或编译步骤，应先为它接入对应的构建方式。本仓库现有三款游戏没有此类依赖。

## 验证

```sh
npm test
npm run test:browser
```

`npm test` 不需要安装依赖，运行大厅存储与筛选、静态资源与预览访问边界、三款游戏的规则验证，以及逸剑风云决 19 场主线策略试跑。

浏览器验证需要 Playwright，可以安装：

```sh
npm install --no-save playwright
npx playwright install chromium
npm run test:browser
```

也可以设置 `PLAYWRIGHT_MODULE` 指向已有 Playwright 包，使用 `BROWSER_PATH` 指定浏览器。在 Windows 上会优先使用已安装的 Edge。测试使用全新的浏览器环境，不接触个人浏览器存档；结果截图保存在被 Git 忽略的 `test-results/`。

`npm run test:browser:dist` 验证构建产物；`node scripts/capture-previews.cjs` 可重新生成三款游戏的实景封面与完整截图。各游戏原来的详细说明和可选测试仍保留在自己的目录中。
